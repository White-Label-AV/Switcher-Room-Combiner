Room Combine Switcher

Plugin version 1.0.0.0 · this document written for 1.0.0.0
White Label AV · Joshua Cerecke · whitelabelav.co.nz · joshua@whitelabelav.co.nz

Description

Room Combine Switcher mirrors the behaviour of the stock Q-SYS Room Combiner component, but instead of mixing audio it synchronises switchers. Rooms are joined and separated by walls using the same wall/room association model. When rooms are combined their switcher selections follow one another; when separated, each room runs independently again.

It adds input restriction: each room can be limited to a subset of the switcher's inputs. When rooms are combined, the group's allowed inputs are the union of its members' — so combining grants each room access to the others' sources, and separating returns each room to its own list. Buttons for inputs a room may not reach are made invisible.

The plugin drives no hardware directly. It exposes control pins that are wired to whatever performs the actual switching — a video matrix plugin, a router component, a Control Script, or logic elsewhere in the design.

Important notes

A room with no valid inputs deselects, and stays deselected. Setting Restrict Mode to Allow with an empty Restrict Inputs box — or Restrict excluding everything — leaves the room with nothing it may select, so every button goes off and both text boxes clear. When inputs are made available again the buttons reappear but the room is not auto-selected; click an input to bring it back. This is deliberate: a room on no input is a legitimate state, and it is what makes Allow toggle off work.

Before 1.0.0.0 this combination raised a runtime error instead.
  • Minimum Q-SYS Designer version: 9.0. The plugin uses no libraries beyond the core Lua API. Developed against QDS 10.1.1.
  • No embedded components. The plugin embeds no mixers, players or gain stages, so it consumes none of the design's channel budget. Multiple instances carry no shared resource cost.
  • No instance limit, but see the execution-limit note below — every plugin, Control Script and Block Controller in a design shares one thread at 30 fps.
  • Execution limit. The room-combine algorithm can exceed the Q-SYS script execution limit when the number of rooms, walls or room/wall associations gets large. Event-handler registration is already chunked across ticks (32 rooms per tick) to mitigate this at startup.
  • Changing Rooms, Walls or Inputs resizes every control array and will break existing wiring to the pins that disappear. Set these before wiring.
  • A range entirely above the room count (e.g. 9-99 with 8 rooms) echoes an inverted string such as 9-8. The parsed selection is correctly empty; only the displayed text is wrong.

Setup and configuration

  1. Place the plugin from Schematic Elements → White Label AV → Room Combine Switcher.
  2. In the Properties pane set Rooms, Walls and Inputs to match the installation. These size every control array, so set them before wiring anything.
  3. Turn on Input Restriction if rooms need to be limited to a subset of inputs. This reveals the per-room Mode and Inputs panel.
  4. Wire the Room N Input pins to whatever performs the switching, and wire the switcher's active-source feedback back into Input Active if you intend to use Auto switch.
  5. For each wall, type the rooms it joins into that wall's Rooms box. Lists and ranges both work — 1-4, 7. Opening the wall combines everything associated with it.
  6. Optionally populate Input Name so the per-room Select by Name combo boxes are meaningful.

No device settings, API keys, physical connections or network configuration are required — the plugin talks to nothing outside the design.

How combining works

  • Every room belongs to a group, even when alone in one. A group is named after its lowest room number, which keeps group identity stable regardless of the order walls were opened.
  • Walls are edges and rooms are nodes. Opening a wall joins every room associated with it; the plugin walks the resulting graph to find each connected set of rooms.
  • Switching happens by group, not by room — provided Link is on.
  • A group's valid inputs are the union of its members'. If the group's current input falls outside that set, the group is moved to the first valid input.

Release notes

1.0.0.0

First release under the White Label AV brand. Restructure, rebrand and documentation pass — no functional change to switching, combining or input restriction.

  • Added the shared White Label AV brand header to the control panel.
  • Source split from a single 1272-line .qplug into src/, assembled by PLUGCC #include directives.
  • Plugin moved to White Label AV in the Schematic Elements tree; PluginInfo completed with the fields the Verification Rubric requires; version now printed to the debug log at start-up.
  • Added this help document and a changelog.
  • Added the Debug Print property. Every automatic print() in the runtime is now gated behind it and defaults to silent; previously they all ran unconditionally.
  • Fixed a runtime error when a room was left with no valid inputs — Allow mode with an empty list, or Restrict excluding everything. A nil input is now handled as a real state rather than dereferenced. Present since 0.98.
  • Fixed: Restrict Mode and Restrict Inputs had no layout entry when Input Restriction was off, leaving them unplaced.
  • Removed the hidden 1×1 code control, a development leftover that was never read. This removes a user pin.
  • PluginInfo.Id lost its -compare development suffix. Designs placed with a -compare build must have the component re-placed.

0.98 and earlier

  • Per-room input restriction with Bypass / Allow / Restrict modes; combined rooms pool their allowed inputs.
  • User-definable LED colours via a comma-separated property.
  • Allow toggle off property, enabling single-input toggle-combiner use.
  • Auto switch, following the most recently activated input per group.
  • Select-by-name combo boxes alongside the numeric selectors.
  • Button disable, sync option and auto switch additions by James Martin, QSC.
